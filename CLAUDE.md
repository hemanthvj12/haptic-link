# HapticLink: notes for Claude

HapticLink for DualSense gives games a virtual wired DualSense fed by a real one on Bluetooth, so haptics, adaptive triggers, rumble and lights work. PeripheralHub (the owner's battery tray app, github.com/hemanthvj12/peripheral-hub) works with it through its control pipe (see "With PeripheralHub"). The README covers usage and the pipe protocol; this file holds the facts behind it.

## Layout
- `drivers/HapticLink.Pad`: UMDF2 HID minidriver in C (own port of Microsoft's vhidmini2, MS-PL sample, not copied) with punktfunk's DualSense descriptor and feature blobs (MIT OR Apache-2.0). Hardware id `HapticLink_DualSense`, UMDF 2.15, `ProcessSharingDisabled`, INF decorated `NTamd64.10.0...19041` (infverif rejects `[*.Filters]` below 18362). A 2 ms→4 ms high-resolution timer thread completes one READ_REPORT per tick. Shared memory `Global\HapticLinkPad0`, layout in `PadShared.h` = `VirtualPad` in the service (a test checks both agree; magic "HLP1"). Pairing MAC is our own so SDL/Steam don't merge it with another virtual pad.
- `drivers/HapticLink.PadHost`: C DLL wrapping `SwDeviceCreate` (`PhPadCreate`/`PhPadClose`). **From .NET JIT code `SwDeviceCreate` fails with 0x8007007E for every input: the callback must be in an image on disk**; the same call from C works. Needs admin; two creations with the same instance → 0x800700B7.
- Driver build: normal MSVC toolset (`$(DefaultPlatformToolset)`) + the `Microsoft.Windows.WDK.x64` NuGet's UMDF headers/stub lib unpacked into `artifacts\wdk` (no WDK install); needs `ntdll.lib` (stub calls `DbgPrintEx`) and `WIN32_NO_STATUS` before `windows.h`. Inf2Cat from the same NuGet. `drivers/build-service.ps1` builds driver + helper + service into `artifacts\service` (signs with a dev certificate unless `-PfxPath`).
- `src/HapticLink.Service` (LocalSystem service `HapticLink`, installed to `%ProgramFiles%\HapticLink\Service`, admins-only ACL; log `%ProgramData%\HapticLink\service.log`). Modes `service`, `console`, `setup`, `remove`. Its `<Version>` is the service's own: the app re-runs setup (one UAC prompt) only when the bundled service is newer, so bump it when the service, driver or helper change.
  - Loop (1 s): switch off → stop; no bridge → find the first Bluetooth DualSense/Edge (`PadConnection.FindBluetoothPads`) and `Bridge.Start`; a dead bridge (no report for 4 s) is released; failures retry after 15 s. The switch is `HKLM\SOFTWARE\HapticLink\Enabled` (missing = on).
  - `Bridge`: reads features 0x05/0x20 (refuses to start if they fail: a half-asleep pad), creates the section (DACL SY, BA, LS for WUDFHost), hides the real pad with HidHide (cloak on, `--dev-hide`, allowed apps = service exe + registered readers; only undoes what it changed; `session-undo.txt` written first and replayed at the next start after a crash), creates the device (enumerator `VID_054C&PID_0CE6&MI_03`, instance `HLINK_PAD_0`, container `484c4e4b-…`), sends the light-bar release, pumps output, shows the speaker and starts `HapticsRelay`.
  - `setup`/`remove` lessons from the first installs (2026-11-02): `remove` deletes the install folder at once unless it runs from inside it (a delayed `rd` once wiped the files a `setup` run straight afterwards had copied, so the service couldn't load its helper DLL); `setup` waits for the old service process to exit and retries each copy briefly (Windows reports "Stopped" a moment before the process is gone, so copying over the exe failed with "in use").
  - Control pipe `HapticLink` (SYSTEM, Admins, Interactive): `HELLO <app>` → `OK <version> 1` (`HELLO PeripheralHub` adds the client exe from `GetNamedPipeClientProcessId` to the readers and HidHide's allowed list), `STATUS` → `OK state|enabled|haptics|mac|message`, `ENABLE`/`DISABLE`. Protocol changes must stay compatible or bump the protocol number: PeripheralHub ships on its own schedule. STATUS's haptics flag means the speaker endpoint is shown, not that recording works (on 2026-11-02 it said 1 while capture kept failing); the log line "haptics: recording the pad speaker" is the real check.
- `src/HapticLink.App`: WinForms tray app (exe `HapticLink`), Velopack 1.2.161 (keep in step with `.config/dotnet-tools.json`), `GithubSource(https://github.com/hemanthvj12/haptic-link)`. First start (and a newer bundled service) runs `service\HapticLink.Service.exe setup` elevated. Uninstall runs `remove`. Icon drawn in code (`IconMaker`; `HapticLink.exe --write-icon <path>` regenerates `Assets\app.ico`). Data in `%APPDATA%\HapticLink` (logs).
- **Releases are installed here at once (owner, 2026-11-02).** After pushing a release tag (only when the owner says), run `./build-installer.ps1 -Version X.Y.Z -Install` instead of waiting for GitHub or watching the Actions run: it applies the locally built package with Velopack's `Update.exe apply` through an Explorer-started `.cmd` and restarts the app (which re-runs setup, one UAC prompt, when the service version went up). **Local builds sign the driver with the release certificate too:** `..\Signing\HapticLink` (outside the repository) holds `HapticLinkPad-release.pfx` and `HapticLinkPad-release.password` (the password DPAPI-encrypted for the owner's Windows user, written by `make-release-cert.ps1`); `build-installer.ps1` uses them whenever `PAD_CERT_PFX` isn't set and refuses `-Install`/`-Publish` without a release certificate. The GitHub secrets hold the same certificate.
- `tests/HapticLink.Tests`: report conversions and the shared-memory layout against `PadShared.h`.
- Releases: `CHANGELOG.md` section first (`## X.Y.Z (date)`), then a `vX.Y.Z` tag on main (only when the owner says) runs `release.yml` → `build-installer.ps1 -Publish`. The driver is signed with the release certificate from secrets `PAD_CERT_PFX_B64`/`PAD_CERT_PASSWORD` (made by `drivers/make-release-cert.ps1`, CN=HapticLink Driver; the owner adds the secrets; never commit the .pfx); `-Publish` refuses without them. Signatures are timestamped. Changing the driver doesn't need a new certificate. The release certificate is `75027197…`. Setup trusts whichever certificate the bundled driver carries; uninstall removes every certificate named `CN=HapticLink Driver`.
- **Published:** 1.0.0 (2026-11-02). Settings → Apps shows the publisher from vpk's `--packAuthors`: `hemanthvj12` (owner's choice: the GitHub name).

## Protocol facts (verified on the owner's DualSense, 2026-11-01)
- **Bluetooth output** `0x31` (78 bytes): `31, seq<<4, 10`, the 47-byte body of USB `0x02`, CRC32 at 74..77. CRC = zlib CRC-32 over `A2` + report (seeded state `~0xEADA2D49`). Windows pads output writes to `OutputReportByteLength` (547) and the pad accepts that; `HidD_SetOutputReport` at the exact size fails with 87.
- **Haptics** `0x32`, **142 bytes** (141 data + id; 141 put the CRC a byte early and nothing played): `32 00 | 91 07 FE 00 00 00 00 FF <counter> | 92 40 <64 s8, L/R interleaved, 3 kHz> | zeros | CRC`.
- The light bar ignores colours until a release: `valid_flag2 0x02` + `lightbar_setup 0x02` (USB bytes 39/42).
- Input: BT `0x31` → USB `0x01` = same fields one byte earlier. Windows pads basic `0x01` BT reports to full length: don't forward them.
- **Haptics relay** (owner: "waaaay better" after these): WASAPI loopback of the pad speaker (4 ch / 48 kHz float), ch 3-4 → 96-tap Hann-sinc low-pass 1.2 kHz → ÷16 → s8; one `0x32` per 10.667 ms on a high-resolution waitable timer (bursts felt late); **silent blocks are sent while the game's stream is open** (gating made the pad swallow short effects: Stellar Blade's menu clicks came through every 3rd–4th time); queue ≤ 2, trimmed to 1 when full for long (a limit of 1 dropped ~8%). **Capture must retry**: right after the endpoint appears `GetService` can fail with 0x88890004.
- **Latency (measured 2026-11-02, test pulses on the owner's pad):** Steam's speaker runs the engine at 10 ms only (`IAudioClient3` shared period 10–10), so loopback hands over 480-frame chunks and a shorter period is impossible. A report holds 10.67 ms, so blocks arrive in a 0–10 ms sawtooth against a steady clock; ~5 ms average wait is the floor for a steady clock. The old free-running clock averaged 11.0 ms queue wait; the clock that follows the blocks (window 48, margin 1.5 ms, late blocks sent on arrival) averages 6.4 ms, ~4 late and ~0 dropped per 2,800 reports. HID writes take 0.6 ms (max ~1.8). The endpoint's loopback timestamps run ~13–17 ms ahead of when we write, so "mix to write" in the log is negative: a relative measure only. What's left is the game's buffer, Bluetooth and the pad. Every 30 s of haptics the log gets a "haptics timing" line.
  - **Our code is at its practical limit (owner agreed, 2026-11-02).** Rumble/triggers: `PumpOutputs` polls every 1 ms and writes straight away (~1 ms). Rejected for haptics: sending blocks as they arrive instead of on a steady clock (~5 ms more, but uneven delivery is what felt late and uneven in the first version) and trimming the filter or margin (1–2 ms, below Bluetooth's own jitter, risks dropped blocks). DSX feels the same or worse, which fits the rest being outside any app. Remaining gains are hardware: Wi-Fi off 2.4 GHz (combo cards share the radio), no Bluetooth audio at the same time, an adapter with line of sight; or a USB cable.
- **Speaker:** a ROOT\MEDIA devnode (marker `HapticLinkPadIndex` in Device Parameters) with hwid `ROOT\SteamStreamingSpeakers`, created with `SetupDiRegisterDeviceInfo` (DIF_REGISTERDEVICE fails from a service), bound to Steam's installed INF (found from a devnode using it or by scanning `oem*.inf`). Stamped through `IPropertyStore`: "Wireless Controller" / "DualSense Wireless Controller", the container id, 4 ch 48 kHz formats. Hidden with `IPolicyConfig::SetEndpointVisibility` when idle; showing it can make it the default output, so `KeepDefault` puts the old one back. **A freshly made endpoint can refuse loopback recording of its own mix format** (AUDCLNT_E_UNSUPPORTED_FORMAT, 0x88890008, seen 2026-11-02 right after the split: the stamped 4-channel format was served by `GetMixFormat`, but the audio engine still ran the driver's old one, from a user process too, so not a service/session-0 issue). `IPolicyConfig::SetDeviceFormat` with the same formats (what Sound settings does) makes the engine apply it at once, and it persists; `Audio.EnsureFormat` does that whenever showing the speaker finds recording refused. Each new devnode gets a new endpoint GUID.
- **HidHide is required for triggers to feel right**: without hiding, games drive both pads.
- COM: create objects via `ComObjects.Create` and cast to interfaces; two `[ComImport]` classes for the MMDevice enumerator clash ("Unable to cast 'MMDeviceEnumerator' to 'MMDeviceEnumerator'").
- A Bluetooth pad once showed "Driver error" (code 10) and had to be re-paired; cause unproven (half-asleep pad with the bridge holding handles). The bridge now lets go after 3 s of silence and refuses to start when the feature reads fail.

## With PeripheralHub
- Owner's rule: **only HapticLink talks to the controller** while it's active. PeripheralHub reads battery (allowed through HidHide via `HELLO PeripheralHub`), shows the waves on the real pad's tile, hides the virtual pad (origin `HLINK_PAD`), and its menu switch sends ENABLE/DISABLE. Future DualSense controls (mic/speaker mute over Bluetooth) go through this pipe; on a cable PeripheralHub can use Windows audio itself.

## Working from this session
- Commands run inside the Claude desktop app's MSIX sandbox (AppData writes are redirected); start exes through Explorer (`Start-Process explorer.exe -ArgumentList '"<path>"'`) to run them outside it. UAC (`runas`) children run outside too.
- Installs: Setup installs per user to `%LOCALAPPDATA%\HapticLink` (start it through Explorer from here); the service goes to `%ProgramFiles%\HapticLink\Service`. Development builds of the service are tried with `setup` from `artifacts\service` elevated, never by installing a local Setup. To go from a development install back to a release: exit the dev tray app, run `artifacts\service\HapticLink.Service.exe remove` elevated (from that copy, not the installed one, so the folder goes at once), then run the release's Setup.
- Talking to the pipe from a throwaway PowerShell (`NamedPipeClientStream`, one line, read one line back) works from this session: handy for STATUS and for ENABLE/DISABLE to restart the bridge.
- **Windows PowerShell 5.1 reads a `.ps1` without a BOM as ANSI**, so non-ASCII text (→, …) written by such a script comes out garbled ("â†’"). Write non-ASCII text with the Edit tool or bash, not a 5.1 script.
